# Šūtum Uno 0.1.0 — первая версия для проверки на стенде

Основа: `firmware/legacy/uno-candidate/LaserShow` (ScriberLatestSimplified).
Дата: 2026-10-06. Плата: **Arduino Uno**, FQBN `arduino:avr:uno`.
Статус: сборка и программные проверки прошли; **на плату не загружено, работа с лазером не проверена**.

Открывать в Arduino IDE: **LaserShow/LaserShow.ino**. Не переименовывать файл отдельно от папки.
Версия выводится при запуске в USB Serial: `Sutum Uno 0.1.0`, 19200 бод.

## Изменения

- Приём пакетов больше не ждёт отсутствующие байты в бесконечном цикле. Межбайтовый таймаут 100 мс сбрасывает незаконченный пакет и немедленно снимает D5.
- После последней завершённой точки с включением лазера отсутствие следующей завершённой команды в течение 1000 мс выключает выход. Отсчёт начинается после движения; штатная синхронная отрисовка текста не считается потерей связи.
- Неверная длина, координаты вне 0–4095, некорректный текст/параметры и переполнение SoftwareSerial приводят к выключению. После переполнения накопленный ввод отбрасывается.
- Текст: 1–55 печатных ASCII-байтов, точная длина N+9, число повторов и speed больше нуля, scale-byte 5–200. Ошибочная команда не получает ACK успеха.
- Принимаются старые команды 01/02 и сетка 03 с двумя байтами; 03 без payload теперь выключает лазер в конце символа текущего RP-проигрывателя. 04 без payload — явное выключение.
- Нулевой/короткий шаг не делит на ноль. Изменение on/off на одинаковой координате сохраняется. Отрицательное перемещение умножается на Q14-масштаб вместо сдвига отрицательного числа.
- При запуске D5 явно устанавливается LOW. Для ошибок используется отдельное немедленное выключение; обычная художественная задержка off() не изменена.
- Удержание кнопки больше не блокирует цикл; debounce 50 мс выполняется по времени. Неиспользуемые ISR отключены, режим обрабатывается один раз за цикл. При смене режима выход гасится, старый пакет/буфер сбрасываются.
- Добавлены счётчики пакетов, ошибок, таймаутов, остановок по отсутствию точек и переполнений.

## Что сохраняется и что ещё не решено

RP2040, его рисунки и хореография, TouchDesigner, распиновка, UART 57600, scale .99, геометрическая коррекция, X-flip и обычные задержки движения сохранены. Новая проверка отклоняет некорректные параметры, которые legacy принимал без проверки.

Остаются: двойная интерполяция, зависимость скорости контуров от предыдущего текста, поздние ACK, обычная задержка перед выключением, синхронная отрисовка текста/сетки и возможное влияние NeoPixel на SoftwareSerial. Это НЕ аппаратный watchdog: таймауты проверяются циклом программы и не прерывают зависший код/долгую отрисовку. Явная команда off также ждёт завершения текущей синхронной операции. Отсутствует CRC, поэтому восстановление после повреждённого потока не гарантирует обнаружение всех искажений. Проблемы питания эта версия не устраняет.

100 мс — выбранный запас над ~11,8 мс передачи максимального 68-байтного пакета при 57600/8N1. 1000 мс — консервативное ограничение простоя после on-точки, намного больше штатной паузы отправителя 6 мс; это не оценка допустимой оптической экспозиции. Порогам нужна проверка на установке. Намеренная освещённая выдержка дольше секунды в таком потоке теперь прервётся.

## Сборка и проверки

Окружение: Arduino CLI 1.3.1; Arduino AVR Boards 1.8.7; Adafruit NeoPixel 1.15.4. Использованы установленные версии, не обновлялись IDE/core/libraries.

```text
arduino-cli compile --fqbn arduino:avr:uno --warnings all --output-dir releases/uno-0.1.0 firmware/uno/0.1.0/LaserShow
```

В этом окружении дополнительно передан конфигурационный YAML установленного IDE. Точный журнал и манифест — в `releases/uno-0.1.0/`.

Исходный снимок: 28018 байт flash, 704 байта глобальной RAM. Версия 0.1.0: 29080 байт flash из 32256; 735 байт глобальной RAM из 2048. Оставшаяся RAM не является измерением максимального использования стека/кучи. Предупреждения legacy о локальных x/y в clipping, неиспользуемом EEPROM и параметрах Arduino core остались; они не скрывались.

Прямые C++ проверки реальных PacketDecoder.h/MotionMath.h: границы payload, неверные параметры, FF/FE внутри данных, таймаут, восстановление и переполнение millis; 2088705 вариантов движения; все 245185 исходных точек Cuneiform.h проходят новый валидатор. Проверки выполнялись на компьютере, без подмен Arduino API; они не моделируют прерывания, SPI или гальванометры.

## Проверка на установке

1. Отключить излучение и разобраться с ослабленным вентилятором/питанием. USB-связь не доказывает исправность питания всей установки.
2. Загрузить через IDE именно этот LaserShow.ino: Arduino Uno, COM15 (порт сообщил владелец). Не использовать Burn Bootloader. Автоматическая загрузка агентом не выполнялась.
3. При отключённом излучении открыть Serial Monitor на 19200: открытие может перезапустить Uno. Проверить строку версии; отправить `?`, чтобы получить счётчики. Не включать постоянный опрос — печать временно отвлекает приёмник.
4. Проверить передачу и окончание символа с RP2040. Тест обрыва выполнять с отключённым излучением; проверить D5 измерением. Загрузку, открытие монитора и переподключение не делать во время оптического прогона.
5. После проверки питания и blanking записать полный прогон: версия, последний символ/слово, длительность остановки, продолжилось ли само, было ли повторение вступления. Счётчики обнуляются при reset; сам факт их нуля после reset не доказывает отсутствие ошибок раньше.

Для отката существует неизменённый кандидат legacy; он не подтверждён как точная копия уже прошитого устройства. До принятия версии не объявлять его гарантированным восстановлением прежнего бинарника.
